# 酒店管理系统 - 异常处理机制说明

## 1. 异常处理架构概述

本系统采用统一的异常处理机制，通过 `@RestControllerAdvice` 全局捕获异常，确保所有API返回统一的响应格式。

### 1.1 架构图

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              客户端请求                                      │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                           Controller 层                                      │
│                    (接收请求、参数校验、调用Service)                          │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                    ┌───────────────┼───────────────┐
                    │               │               │
                    ▼               ▼               ▼
            ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
            │ 正常执行    │ │ 业务异常    │ │ 系统异常    │
            │ 返回结果    │ │ Business    │ │ Exception   │
            └──────┬──────┘ │ Exception   │ │             │
                   │        └──────┬──────┘ └──────┬──────┘
                   │               │               │
                   │               └───────┬───────┘
                   │                       │
                   │                       ▼
                   │        ┌─────────────────────────────┐
                   │        │   GlobalExceptionHandler    │
                   │        │   (@RestControllerAdvice)   │
                   │        └──────────────┬──────────────┘
                   │                       │
                   └───────────────────────┤
                                           ▼
                            ┌─────────────────────────────┐
                            │      统一响应格式 Result     │
                            │  { code, message, data }    │
                            └─────────────────────────────┘
                                           │
                                           ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                              客户端响应                                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 核心类说明

### 2.1 统一响应类 (Result.java)

```java
package com.hotel.common;

/**
 * 统一响应结果
 * 所有API接口都返回此格式
 */
@Data
public class Result<T> implements Serializable {

    /** 状态码 */
    private int code;
    
    /** 提示信息 */
    private String message;
    
    /** 响应数据 */
    private T data;

    // ==================== 成功响应 ====================
    
    /** 成功（无数据） */
    public static <T> Result<T> success() {
        return new Result<>(200, "操作成功", null);
    }

    /** 成功（带数据） */
    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data);
    }

    /** 成功（自定义消息） */
    public static <T> Result<T> success(String message, T data) {
        return new Result<>(200, message, data);
    }

    // ==================== 错误响应 ====================
    
    /** 通用错误 */
    public static <T> Result<T> error(String message) {
        return new Result<>(500, message, null);
    }

    /** 自定义错误码 */
    public static <T> Result<T> error(int code, String message) {
        return new Result<>(code, message, null);
    }

    /** 未授权 (401) */
    public static <T> Result<T> unauthorized(String message) {
        return new Result<>(401, message, null);
    }

    /** 禁止访问 (403) */
    public static <T> Result<T> forbidden(String message) {
        return new Result<>(403, message, null);
    }
}
```

### 2.2 业务异常类 (BusinessException.java)

```java
package com.hotel.common;

/**
 * 业务异常
 * 用于业务逻辑中的可预期异常
 */
@Getter
public class BusinessException extends RuntimeException {

    /** 错误码 */
    private final int code;

    /**
     * 构造方法（默认500错误码）
     * @param message 错误信息
     */
    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }

    /**
     * 构造方法（自定义错误码）
     * @param code 错误码
     * @param message 错误信息
     */
    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }
}
```

### 2.3 全局异常处理器 (GlobalExceptionHandler.java)

```java
package com.hotel.config;

/**
 * 全局异常处理器
 * 统一捕获并处理所有异常，返回标准格式响应
 */
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /**
     * 处理业务异常
     * 场景：业务逻辑中主动抛出的异常
     * 示例：throw new BusinessException("用户名已存在")
     */
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusinessException(BusinessException e) {
        log.error("业务异常: {}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    /**
     * 处理认证异常
     * 场景：用户名或密码错误
     */
    @ExceptionHandler(BadCredentialsException.class)
    public Result<?> handleBadCredentialsException(BadCredentialsException e) {
        log.error("认证异常: {}", e.getMessage());
        return Result.unauthorized("用户名或密码错误");
    }

    /**
     * 处理权限异常
     * 场景：用户无权访问某资源
     */
    @ExceptionHandler(AccessDeniedException.class)
    public Result<?> handleAccessDeniedException(AccessDeniedException e) {
        log.error("权限异常: {}", e.getMessage());
        return Result.forbidden("没有权限访问");
    }

    /**
     * 处理参数校验异常
     * 场景：@Valid 注解校验失败
     * 示例：@NotBlank(message = "用户名不能为空")
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleMethodArgumentNotValidException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining(", "));
        log.error("参数校验异常: {}", message);
        return Result.error(400, message);
    }

    /**
     * 处理参数绑定异常
     * 场景：请求参数类型不匹配
     */
    @ExceptionHandler(BindException.class)
    public Result<?> handleBindException(BindException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining(", "));
        log.error("参数绑定异常: {}", message);
        return Result.error(400, message);
    }

    /**
     * 处理约束违反异常
     * 场景：@Validated 注解校验失败
     */
    @ExceptionHandler(ConstraintViolationException.class)
    public Result<?> handleConstraintViolationException(ConstraintViolationException e) {
        String message = e.getConstraintViolations().stream()
                .map(ConstraintViolation::getMessage)
                .collect(Collectors.joining(", "));
        log.error("约束违反异常: {}", message);
        return Result.error(400, message);
    }

    /**
     * 处理其他未知异常
     * 场景：系统内部错误、数据库异常等
     */
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        log.error("系统异常: ", e);
        return Result.error("系统异常，请联系管理员");
    }
}
```

## 3. 错误码规范

### 3.1 HTTP状态码映射

| 错误码 | HTTP状态 | 说明 | 使用场景 |
|--------|----------|------|----------|
| 200 | OK | 成功 | 请求处理成功 |
| 400 | Bad Request | 参数错误 | 参数校验失败、格式错误 |
| 401 | Unauthorized | 未授权 | 未登录、Token过期、密码错误 |
| 403 | Forbidden | 禁止访问 | 无权限访问资源 |
| 404 | Not Found | 资源不存在 | 请求的资源不存在 |
| 500 | Internal Error | 服务器错误 | 系统内部异常 |

### 3.2 业务错误码定义

| 错误码 | 说明 | 示例 |
|--------|------|------|
| 1001 | 用户相关错误 | 用户名已存在 |
| 1002 | 认证相关错误 | 密码错误 |
| 2001 | 房间相关错误 | 房间不可用 |
| 2002 | 预订相关错误 | 预订已取消 |
| 2003 | 入住相关错误 | 已退房 |
| 3001 | 财务相关错误 | 账单已支付 |

## 4. 异常处理流程

### 4.1 业务异常处理流程

```
Service层检测到业务错误
        │
        ▼
throw new BusinessException("错误信息")
        │
        ▼
GlobalExceptionHandler.handleBusinessException()
        │
        ▼
记录日志: log.error("业务异常: {}", e.getMessage())
        │
        ▼
返回: Result.error(code, message)
        │
        ▼
前端接收: { code: 500, message: "错误信息", data: null }
        │
        ▼
前端显示: ElMessage.error("错误信息")
```

### 4.2 参数校验异常处理流程

```
Controller接收请求参数
        │
        ▼
@Valid 注解触发校验
        │
        ▼
校验失败抛出 MethodArgumentNotValidException
        │
        ▼
GlobalExceptionHandler.handleMethodArgumentNotValidException()
        │
        ▼
提取所有字段错误信息并拼接
        │
        ▼
返回: Result.error(400, "字段1错误, 字段2错误")
        │
        ▼
前端显示: ElMessage.error("字段1错误, 字段2错误")
```

### 4.3 认证异常处理流程

```
用户发起请求
        │
        ▼
JwtAuthenticationFilter 拦截
        │
        ├── Token不存在 ──▶ 返回401
        │
        ├── Token过期 ──▶ 返回401
        │
        └── Token有效 ──▶ 继续执行
                │
                ▼
        Spring Security 权限校验
                │
                ├── 无权限 ──▶ AccessDeniedException ──▶ 返回403
                │
                └── 有权限 ──▶ 执行业务逻辑
```

## 5. 使用示例

### 5.1 Service层抛出业务异常

```java
@Service
public class ReservationService {

    public void createReservation(ReservationRequest request) {
        // 检查房间是否可用
        Room room = roomMapper.selectById(request.getRoomId());
        if (room == null) {
            throw new BusinessException(404, "房间不存在");
        }
        if (room.getStatus() != 0) {
            throw new BusinessException("该房间当前不可预订");
        }
        
        // 检查日期是否冲突
        boolean hasConflict = checkDateConflict(request);
        if (hasConflict) {
            throw new BusinessException("所选日期已被预订");
        }
        
        // 正常业务逻辑...
    }
}
```

### 5.2 Controller层参数校验

```java
@RestController
@RequestMapping("/api/reservation")
public class ReservationController {

    @PostMapping
    public Result<?> create(@Valid @RequestBody ReservationRequest request) {
        // @Valid 会自动校验参数
        // 校验失败会抛出 MethodArgumentNotValidException
        reservationService.createReservation(request);
        return Result.success("预订成功");
    }
}

// DTO类
@Data
public class ReservationRequest {
    
    @NotNull(message = "客户ID不能为空")
    private Long customerId;
    
    @NotNull(message = "房型ID不能为空")
    private Long roomTypeId;
    
    @NotNull(message = "入住日期不能为空")
    @Future(message = "入住日期必须是将来的日期")
    private LocalDate checkInDate;
    
    @NotNull(message = "离店日期不能为空")
    private LocalDate checkOutDate;
}
```

### 5.3 前端异常处理

```javascript
// request.js - 响应拦截器
request.interceptors.response.use(
  response => {
    const res = response.data
    if (res.code !== 200) {
      // 显示错误提示
      ElMessage.error(res.message || '请求失败')
      
      // 401 未授权 - 跳转登录
      if (res.code === 401) {
        store.dispatch('logout')
        router.push('/login')
      }
      
      return Promise.reject(new Error(res.message))
    }
    return res
  },
  error => {
    ElMessage.error(error.message || '网络错误')
    return Promise.reject(error)
  }
)

// 业务代码中使用
const handleSubmit = async () => {
  try {
    await createReservation(form)
    ElMessage.success('预订成功')
  } catch (error) {
    // 错误已在拦截器中处理，这里可以做额外处理
    console.error('预订失败:', error)
  }
}
```

## 7. 最佳实践

### 7.1 异常处理原则

1. **不要吞掉异常**：所有异常都应该被记录或处理
2. **使用具体异常**：优先使用 BusinessException 而非通用 Exception
3. **提供有意义的错误信息**：错误信息应该对用户友好
4. **区分客户端错误和服务端错误**：使用正确的HTTP状态码

### 7.2 代码规范

```java
// ✅ 推荐：使用具体的业务异常
if (user == null) {
    throw new BusinessException(404, "用户不存在");
}

// ❌ 不推荐：返回null或使用通用异常
if (user == null) {
    return null;  // 调用方需要判断null
}

// ❌ 不推荐：捕获异常后不处理
try {
    doSomething();
} catch (Exception e) {
    // 什么都不做
}

// ✅ 推荐：捕获后记录或重新抛出
try {
    doSomething();
} catch (Exception e) {
    log.error("操作失败: ", e);
    throw new BusinessException("操作失败，请重试");
}
```
